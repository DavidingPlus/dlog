# SkipList

这是一个基于内存的跳表练习实现。它按 key 排序保存键值对，支持插入、查找、删除、显示和统计元素个数。`dumpFile()` 可以将当前数据保存到文件，`loadFile()` 可以读取文件中的键值对并合并到当前跳表。

## 跳表结构

跳表可以理解为一条包含所有节点的底层有序链表，加上若干条由部分节点组成的上层快速通道。查找时从高层向右前进，遇到不应越过的节点后下降一层，最后在第 0 层确认目标。

```text
Level 2: HEAD ─────────> 10 ─────────────> 70
Level 1: HEAD ──> 4 ───> 10 ───> 30 ────> 70
Level 0: HEAD ──> 1 ───> 4 ───> 10 ─> 30 ─> 50 ─> 70
```

每个 key 对应一个 `Node` 对象。节点在图中跨越多层，表示同一个节点参与了多层链表，不代表每层各有一份节点。

### `Node` 中的前向指针

`Node<K, T>` 保存 key、value、最高层编号 `m_nodeLevel`，以及 `m_forward` 向量。

- `m_forward[i]` 指向第 `i` 层中该节点右侧的下一个节点。
- `m_forward[0]` 是底层链表中的后继指针，不是指向“下一层”的指针。
- 节点参与第 `0` 层到 `m_nodeLevel` 层，因此向量大小为 `m_nodeLevel + 1`。
- `m_forward` 中保存的是节点指针；这些指针槽位本身不会负责删除所指向的节点。

## 层编号与跳表高度

本实现用**最高层编号**表示层级上限，而不是用层数表示：

- 构造 `SkipList(6)` 后，允许的层编号是 `0..6`，共 7 层。
- `m_maxLevel` 是允许的最高层编号。
- `m_skipListLevel` 是当前实际使用的最高层编号。空表从第 0 层开始，因此初始值为 0。
- 节点的 `m_nodeLevel` 和 `getRandomLevel()` 的返回值也都是最高层编号。

例如，节点的最高层编号为 2 时，它参与第 0、1、2 层，`m_forward` 有 3 个槽位。

## 操作流程

### 查找 `searchElement`

1. 从 `m_skipListLevel` 层的头节点开始。
2. 在当前层向右越过所有 key 小于目标 key 的节点。
3. 下降一层，继续从当前位置向右查找。
4. 到达第 0 层后检查下一个节点是否匹配。

找到时返回 `true`，否则返回 `false`。预期查找时间为 `O(log n)`；最坏情况仍可能遍历 `O(n)` 个节点。

### 插入 `insertElement`

1. 从高层向下查找插入位置，并将每层的前驱节点保存在 `update[i]` 中。
2. 检查第 0 层的候选节点。若 key 已存在，不插入并返回 `false`。
3. 调用 `getRandomLevel()` 随机选择新节点的最高层编号。
4. 若新节点会建立更高的层，新层的前驱都是头节点。
5. 对新节点参与的每一层，先让新节点指向原后继，再让前驱指向新节点。
6. 更新 `m_skipListLevel` 和 `m_size`，成功时返回 `true`。

`update[i]` 的作用是记住每层需要改动的前驱；它不保存新节点，也不是所有节点的索引表。

### 随机层级 `getRandomLevel`

`main()` 在程序启动时调用一次 `std::srand(static_cast<unsigned int>(std::time(nullptr)))`，为运行库的 `std::rand()` 序列播种。不要在 `getRandomLevel()` 或 `SkipList` 构造函数里重复调用 `srand()`：它会重置运行库维护的随机序列，而不是初始化某个跳表对象自己的随机状态。

`getRandomLevel()` 每次调用 `std::rand() % 2` 做升层判断：结果为 1 就提升一层，结果为 0 就停止，直到到达 `m_maxLevel`。返回值是新节点的最高层编号，新节点会参加第 0 层到返回层的所有层。

若要复现相同的随机序列，可在 `main()` 中临时用固定 seed，例如 `std::srand(1234)`；使用 `std::time(nullptr)` 时，同一秒内启动程序可能得到相同 seed。`rand/srand` 状态由 C 运行库维护，不是每个 `SkipList` 独立持有的状态；不同运行库的状态共享范围可能不同，但每个对象自己的锁无法协调不同跳表对运行库随机状态的访问，因此这版做法适合当前单跳表学习示例。

### 删除 `deleteElement`

1. 像插入一样从高层向下查找，并在 `update[i]` 中记录每层的前驱。
2. 检查第 0 层的候选节点；找不到时直接返回。
3. 从底层向上，让每层前驱的 `m_forward[i]` 指向目标节点原来的后继，从而绕过目标节点。
4. 所有层的链接都更新后，只对目标 `Node` 执行一次 `delete`，并减少 `m_size`。
5. 若当前最高层变空，就降低 `m_skipListLevel`。第 0 层始终保留。

### 保存 `dumpFile`

沿第 0 层遍历所有节点，将每个键值对写成一行 `key:value`，保存到当前工作目录下的 `store/dumpFile`。目录不存在时自动创建，每次保存都会覆盖旧文件；空跳表会生成空文件。保存期间持有独占锁，使同一对象的保存操作串行执行，并阻止插入和删除修改正在保存的数据。

文件流使用局部变量管理，目录创建、文件打开或写入失败时会抛出异常。保存的是键值数据，节点指针和随机层级不会写入文件。此文本格式未做转义，因此 key 中的冒号及 key/value 中的换行需要在后续设计文件格式时处理。

### 加载 `loadFile`

当前加载接口按参考实现支持 `int` key、`std::string` value。从当前工作目录的 `store/dumpFile` 逐行读取，用 `find()` 和 `substr()` 按第一个冒号拆分，再用 `std::stoi()` 将 key 转成整数并调用 `insertElement()`。缺少冒号、key 为空或 value 为空的行会跳过，value 中的空格和后续冒号保留。文件打开失败或 key 无法转换时抛出异常；加载是逐行插入的，后续行失败时，之前成功插入的记录会保留。

加载保留当前跳表已有的数据，重复 key 保留最先插入的值，新节点重新随机生成层级。`insertElement()` 自己负责加锁，`loadFile()` 不再额外持有跳表锁。这个学习版本的文件保存和加载由调用方顺序执行。

### 清理与析构

跳表析构时从头节点的 `m_forward[0]` 开始，沿底层链表循环删除所有数据节点，最后删除头节点。每次先保存后继指针，再删除当前节点，避免读取已释放的内存。底层链表包含全部节点，因此上层指针无需再逐层删除；循环清理也避免了大量节点带来的递归栈溢出。

## 线程安全与互斥锁

每个 `SkipList` 对象有一把 `std::shared_mutex`，用于保护节点指针、层级和元素数量。插入、删除和保存取得独占锁；查找、显示和 `size()` 取得共享锁。因此对**同一个对象**，多个读操作可以并行，读操作与写操作不能同时进行，多个写操作也会依次进行。

独占锁通过 `std::unique_lock<std::shared_mutex>` 管理，共享锁通过 `std::shared_lock<std::shared_mutex>` 管理。函数离开作用域时锁会自动释放，包括提前 `return` 的路径，避免手动加锁后漏掉解锁。

查找和显示目前会向 `std::cout` 输出信息；多个读操作同时输出时，文本可能交错。共享锁保护的是跳表数据，不保证不同输出调用组成一整块连续文本。

对象析构期间不能再有其他线程访问它。调用方必须先停止并等待这些线程结束，再销毁 `SkipList`；析构函数无法靠对象自身的 mutex 安全处理与析构同时发生的调用。

## 当前示例

`main1.cpp` 使用 `SkipList<int, std::string>`，插入若干英文字符串，并尝试两次插入 key `19`。第二次插入会因为 key 已存在而失败，原来的 value 保持不变。示例随后查找 key `9` 和 `18`，显示跳表，再删除 key `3` 和 `7`。

## 压力测试

`main3.cpp` 使用标准 C++ 的 `std::thread` 创建工作线程，用 `join()` 等待全部线程完成。每次运行先完成插入阶段，再执行查询阶段，分别输出耗时；默认各执行 10 万次操作。Windows/MSVC 可直接使用；Linux 构建目标已配置 `-pthread` 编译和链接选项。

```text
xmake run SkipListStressTest
```

文件开头的参数决定测试负载：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `kThreadCount` | `1` | 工作线程数量，所有线程共享同一个跳表 |
| `kTestCount` | `100000` | 每个阶段合计的操作次数，包含重复插入和查询未命中 |

每个线程拥有独立的 `std::mt19937`，通过 `std::uniform_int_distribution` 生成 `0..kTestCount-1` 的随机 key，不受 C 运行库 `RAND_MAX` 的限制。节点层级仍沿用跳表内部的 `std::rand()`；程序入口保留 `std::srand()` 播种。

测试用 `std::chrono::steady_clock` 统计耗时，输出单位为秒。计时包括线程创建、随机 key 生成、跳表操作及其日志输出，不包含退出时的跳表清理。随机 key 可能重复，因此插入次数不等于最终节点数量。插入阶段完成后会打印 `skipList size`。

当前跳表每次操作仍会打印日志，控制台输出会影响性能结果。测试没有统计成功插入数和查询命中数，也不执行读写混合、删除或文件保存/加载。

## 当前实现的边界

- 插入和删除只修改内存；只有主动调用 `dumpFile()` 才会保存快照，`loadFile()` 用于读取保存的数据。
- 同一个对象上的读操作可以并行；任何写操作会与其他读写操作互斥。
- key 类型需要支持 `<` 和 `==`；显示和保存要求 key、value 可输出到流。`loadFile()` 当前按 `int` key、`std::string` value 实现。
- `std::rand()` 的低位随机质量有限；该实现用于学习跳表层级选择，不应用于安全或密码学场景。
