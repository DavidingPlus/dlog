# 异步日志基准测试完善计划

按以下顺序实施，使用公开 Logger 接口，保留文件校验与成功清理、失败保留的行为；性能数字仅用于观察，不设通过阈值。

1. **重复与汇总**：各吞吐场景独立创建 Logger 和输出文件，按指定次数重复，输出每次提交及排空总耗时和吞吐量，分别计算吞吐量中位数；核对每轮记录数。
2. **低频输出延迟**：逐条提交并等待后台回调，测量提交前至回调收到数据的耗时；输出样本数、平均值、P95 和最大值，限时等待防止失败时无限阻塞。这不是写盘或持久化延迟。
3. **慢输出积压**：回调每批固定等待，记录提交时间、提交后排空时间、总耗时和完整记录数；批次数不同会影响结果，不将字节数当成内存峰值。
4. **多个 Logger 共享线程池**：同时向慢输出和普通计数输出的 Logger 提交记录，报告各自完成时间、整体排空时间并核对各自记录数；不把线程调度结果解释为公平性保证。

验证：在可用构建环境中运行小规模及默认参数，核对每轮数量、延迟样本、慢输出与多 Logger 的输出、参数错误及成功清理；记录未覆盖的平台。Release 性能应多次运行并记录硬件、系统和构建配置。

2026-11-13：四项场景已实现。Windows MSVC x64 Debug 下构建成功，小规模测试覆盖单次、双次运行及记录数不能整除线程数；默认参数下 20 轮吞吐场景与额外场景通过数量核对，低频获得 100 个样本，并完成文件清理。零重复次数被拒绝。Debug 结果不作为性能结论；Linux、Release 性能和真实慢存储尚未验证。
