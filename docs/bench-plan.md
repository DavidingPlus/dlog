# 异步日志基准测试完善计划

按以下顺序实施，使用公开 Logger 接口，保留文件校验与成功清理、失败保留的行为；性能数字仅用于观察，不设通过阈值。

1. **重复与汇总**：各吞吐场景独立创建 Logger 和输出文件，按指定次数重复，输出每次提交及排空总耗时和吞吐量，分别计算吞吐量中位数；核对每轮记录数。
2. **低频输出延迟**：逐条提交并等待后台回调，测量提交前至回调收到数据的耗时；输出样本数、平均值、P95 和最大值，限时等待防止失败时无限阻塞。这不是写盘或持久化延迟。
3. **慢输出积压**：回调每批固定等待，记录提交时间、提交后排空时间、总耗时和完整记录数；批次数不同会影响结果，不将字节数当成内存峰值。
4. **多个 Logger 共享线程池**：同时向慢输出和普通计数输出的 Logger 提交记录，报告各自完成时间、整体排空时间并核对各自记录数；不把线程调度结果解释为公平性保证。

验证：在可用构建环境中运行小规模及默认参数，核对每轮数量、延迟样本、慢输出与多 Logger 的输出、参数错误及成功清理；记录未覆盖的平台。Release 性能应多次运行并记录硬件、系统和构建配置。

2026-11-13：四项场景已实现。Windows MSVC x64 Debug 下构建成功，小规模测试覆盖单次、双次运行及记录数不能整除线程数；默认参数下 20 轮吞吐场景与额外场景通过数量核对，低频获得 100 个样本，并完成文件清理。零重复次数被拒绝。Debug 结果不作为性能结论；Linux、Release 性能和真实慢存储尚未验证。

# Google Benchmark 迁移方案

## 目标与边界

将现有异步性能测试迁移到 Google Benchmark，保留中文场景说明、记录数核验和成功清理、失败保留文件的行为。框架负责执行测试、重复统计和 JSON 输出；本次不绘图，不改变 dlog 库本身、输出策略或发布包依赖。Google Benchmark 是仅供 bench 构建使用的依赖。

## 场景和计时

| 现有场景 | 迁移后的测试 | 计时与校验 |
| --- | --- | --- |
| 单、多生产者的计数输出和普通文件输出 | 每次执行创建独立 Logger，以固定消息总数运行一个批次；生产者数覆盖 1 和 4 | 从生产者同时开始到结束为提交耗时，再等待 stop() 得到总耗时；核对输出记录数，分别报告提交和含排空的吞吐量。 |
| 低频延迟 | 一次测试逐条提交 100 条，每条等待回调后再进行下一条 | 统计提交前到回调收到数据的平均、P95 和最大值；不是文件落盘延迟；有限超时及样本数检查保留。 |
| 慢输出 | 每批回调等待 1 毫秒，运行多生产者批次 | 报告提交、总耗时、排空耗时与批次数，并核对记录数；不把字节数称为内存峰值。 |
| 共享线程池 | 一个线程交替向普通和慢输出的两个 Logger 提交 | 保留两个 Logger 的完成时间、全部排空耗时和各自记录数校验；不承诺公平性。 |

框架每个测试迭代对应一个完整批次；采用手动时间上报明确计时范围，创建 Logger、校验和清理不计入主时间。吞吐测试同时以数值计数器报告提交和完整吞吐；低频和共享池的各项额外指标也通过数值计数器输出。默认每项按固定单次批次执行，使用框架的 repetitions 指定重复次数，避免自动校准时重复创建并由 Manager 长期持有大量 Logger。记录数、生产者数用 dlog 命令行选项配置，并写入框架的 JSON 上下文。

## 文件和错误处理

- 使用可执行文件目录下独立子目录；文件 Logger 排空、校验并关闭后，所有测试和 Manager 关闭成功再删除本次文件与目录。
- 各场景异常、超时或校验失败必须被框架记录为失败；测试失败或清理失败时保留剩余文件并报告路径。框架测试失败不能被误报为进程成功。
- 控制台中文说明保留；Google Benchmark 自带的表头、命令参数和 JSON 字段可能是英文，在 README 解释其含义。
- 不把历史 bench 数字与框架新输出视作完全可比：统计口径、测试参数、线程创建及排空时间必须说明。

## 验收

1. 普通构建、测试和发布依赖不要求 Google Benchmark；按需构建 bench 时才解析并链接该依赖。
2. 在 Windows 可用环境构建并运行全部场景，检查单线程与多线程、重复次数、记录数、低频样本、慢输出和共享池结果，确认正常清理。
3. 模拟失败，确认失败状态和文件保留；检查 JSON 具有每轮结果和计数器，并测试无效参数和场景筛选。
4. 同步 README 用法和指标口径，记录未验证的平台、构建模式、性能和数据完整性边界。

状态：已实施。Windows MSVC x64 Release 使用 Google Benchmark v1.9.5 验证了全部 7 个场景、2 次重复、17 条记录及 3 个生产者，JSON 包含 14 条单次结果和汇总，正常输出目录已清理；默认 100000 条配置也运行通过。隔离副本模拟文件记录校验失败，框架和 JSON 均报告错误、进程返回失败并保留两份日志。已验证英文场景前缀筛选、无效参数拒绝，以及关闭 bench 后普通库构建。Linux、Windows Debug 和跨平台性能比较尚未验证；生成的数字仅证明测试执行，不作为性能结论。
